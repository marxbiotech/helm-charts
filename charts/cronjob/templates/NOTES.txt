The schedule is suspended and will not fire. Resume it with:
  helm upgrade ... --set cronJob.suspend=false
or, out of band:
  kubectl patch cronjob/{{ include "cronjob.cronJobName" . }} -n {{ .Release.Namespace }} -p '{"spec":{"suspend":false}}'
{{- end }}

Check the schedule:
  kubectl get cronjob/{{ include "cronjob.cronJobName" . }} -n {{ .Release.Namespace }}

List the runs it created:
  kubectl get jobs -n {{ .Release.Namespace }} \
    --selector app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=cronjob

Follow the most recent run:
  kubectl logs -n {{ .Release.Namespace }} -f --tail=-1 \
    job/$(kubectl get jobs -n {{ .Release.Namespace }} \
      --selector app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=cronjob \
      --sort-by=.metadata.creationTimestamp -o name | tail -1 | cut -d/ -f2)

Trigger an out-of-band run without waiting for the schedule:
  kubectl create job --from=cronjob/{{ include "cronjob.cronJobName" . }} \
    {{ include "cronjob.cronJobName" . }}-manual -n {{ .Release.Namespace }}
